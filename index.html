dev/test → csp  Break-Even Analyser

Reprices a Dev/Test subscription's actual usage at Azure Plan (CSP) retail rates and finds the partner discount at which the move makes commercial sense.

🔒 Runs entirely in your browser — no data is uploaded

01Get the usage data

One full calendar month at subscription scope. Three ways to get it — the first is the 30-second one and is what most people already have. All of them now work; the panel below tells you exactly what each one buys you.

  1. Azure portal → Cost Management → Cost analysis, scoped to the Dev/Test subscription.
  2. Switch the view to Cost by resource (the built-in CostByResource view). It carries ServiceName, Meter, ResourceLocation and ResourceId — everything the analysis needs.
  3. Set the date range to one full calendar month, then Download → CSV.

This file has no Quantity and no unit prices, so the tool derives quantities by dividing each line's cost by that meter's retail unit rate from the Azure Retail Prices API. That recovers VM hours and the reservation model. It can't detect a per-meter Dev/Test rate discount, so the break-even it reports is a floor — if the estate is mostly VMs and storage (where Dev/Test and PAYG rates match) that floor is the real answer. Needs outbound access to prices.azure.com.

  1. Open Azure Cloud Shell (the >_ icon in the portal top bar), Bash.
  2. Paste the block below. It writes devtest-usage.csv and pops a download.
# az account set --subscription "Visual Studio Professional Subscription"   # if it isn't the current one
sub=$(az account show --query id -o tsv)
end=$(date -u +%Y-%m-01); start=$(date -u -d "$end -1 month" +%Y-%m-%d)
url="https://management.azure.com/subscriptions/$sub/providers/Microsoft.Consumption/usageDetails?api-version=2021-10-01&metric=ActualCost&%24expand=meterDetails&%24top=1000&%24filter=properties%2FusageStart%20ge%20%27$start%27%20and%20properties%2FusageEnd%20lt%20%27$end%27"
echo 'MeterId,MeterCategory,MeterSubCategory,MeterName,UnitOfMeasure,Quantity,EffectivePrice,UnitPrice,PayGPrice,CostInBillingCurrency,BillingCurrency,ResourceLocation,ChargeType,PublisherType,ResourceId,Date' > devtest-usage.csv
while [ -n "$url" ]; do
  r=$(az rest --method get --url "$url" --only-show-errors -o json)
  echo "$r" | jq -r '.value[]|.properties|[.meterId,(.meterDetails.meterCategory//.meterCategory//""),(.meterDetails.meterSubCategory//.meterSubCategory//""),(.meterDetails.meterName//.meterName//""),(.meterDetails.unitOfMeasure//.unitOfMeasure//""),.quantity,.effectivePrice,.unitPrice,(.payGPrice//""),(.cost//.costInBillingCurrency),(.billingCurrency//.billingCurrencyCode),.resourceLocation,.chargeType,(.publisherType//"Azure"),.resourceId,.date]|@csv' >> devtest-usage.csv
  url=$(echo "$r" | jq -r '.nextLink // empty')
done
echo "rows: $(( $(wc -l < devtest-usage.csv) - 1 ))"; download devtest-usage.csv

This is the same data a scheduled export produces — including PayGPrice — without waiting for an export to run. Every line is then priced entirely offline; the Retail Prices API is only used for reservation rates.

  1. Cost Management → Exports → Create → Cost and usage details (actual cost).
  2. Scope: the Dev/Test subscription. Granularity: daily. Period: month-to-date or a chosen month, to a storage account.
  3. Run it once, then download the CSV from the container and drop it below.

Richest file and fully offline — it carries Quantity, MeterId and PayGPrice per line, so the tool sees exactly where Dev/Test rates undercut PAYG rather than assuming they match. Worth it if you're building a real proposal; the Cloud Shell route gets you the same columns in a minute.

04Reservation savings on Azure Plan

Dev/Test can't use reserved instances — Azure Plan (CSP) can. Committing steady-state compute to a 1- or 3-year reservation cuts the CSP rate well below PAYG, which is often what tips the move. 07What the numbers can't show

  • No SLA on Dev/Test. Dev/Test offers carry no financially-backed SLA. Azure Plan (CSP) restores standard SLAs — worth real money if these workloads matter.
  • Production is prohibited on Dev/Test. If any of this estate is quietly running production, moving to CSP is a compliance fix, not just a commercial choice.
  • Visual Studio subscription dependency. Dev/Test rates require active Visual Studio subscribers. CSP removes that dependency and its per-seat cost.
  • Marketplace & purchase charges are excluded from the repricing — they bill identically on either offer.
  • SQL Server on Dev/Test also bills without the SQL licence meter. If the estate includes SQL VMs, the true CSP cost is higher than shown unless AHB covers SQL too.
  • Reservations are modelled from public retail rates (or, where the Retail Prices API is unreachable, estimated from the export's PAYG rate and the assumed discounts you set) and assume steady-state utilisation of the reserved instances. Real commitments carry cancellation/exchange rules and capacity considerations, and a partner may pass additional margin on top — treat the reservation saving as indicative, and size it to genuinely predictable base load only. Savings plans (not modelled here) are an alternative with more flexibility and typically slightly smaller discounts.
